# Java 비동기 처리하기 (MOPL Lost Update) — Q&A

### Q1. synchronized 해결책과 실제 프로젝트의 원자적 UPDATE 방식 비교

> **Q.** "synchronized (lock) { ... }로 감싸면 한 번에 하나의 스레드만 그 블록에 들어갈 수 있어 값이 정확하게 누적된다" 이 말이 정확히 무슨 말이야? 해결책에서 나온 설명대로면 임계 영역을 synchronized (lock) { ... }로 감싸라는거잖아 근데 내가 프로젝트에서 사용한 방식은 컬럼을 수정했거든. 이게 정확히 어떤 방식인지 설명해줘. 내가 비전공자이고 이해시켜야한다는 가정으로 답변해.
>
> 두 가지를 순서대로 풀어본다. 둘 다 "여러 명이 동시에 숫자를 하나씩 늘리려고 할 때 몇 명분이 사라지는 문제"를 해결하는 방법인데, **완전히 다른 방식**이다.
>
> **① `synchronized(lock){...}`가 정확히 뭘 하는가**
>
> - 문제 상황: 공유된 숫자(`count`)를 5명(스레드 5개)이 각자 +1 하려고 한다. `count++`는 사실 "① 지금 값 읽기 → ② +1 계산 → ③ 다시 저장"이라는 3단계다.
> - **보호가 없으면**: 5명이 거의 동시에 몰리면, 여러 명이 ①번(읽기)을 동시에 해서 다들 "지금 0이구나"라고 보고, 각자 ②③번을 거쳐 전부 "1"이라고 저장해버린다. 결과: 5번 늘어나야 하는데 1번만 늘어남.
> - **`synchronized`로 감싸면**: 이 3단계 전체를 "한 사람만 들어갈 수 있는 방"으로 만든다. 손님 1이 방에 들어가서 ①②③번을 전부 마치고 나가야, 그다음에야 손님 2가 들어갈 수 있다. 그래서 손님 2가 ①번(읽기)을 할 때는 이미 손님 1이 써놓은 "1"이라는 값을 보게 된다. 이 순서를 강제로 지키게 만드니까, 5명이 차례로 1→2→3→4→5로 정확히 쌓인다.
> - 즉 `synchronized`는 "여러 사람이 직접 값을 읽고 계산하고 쓰는 행위" 자체는 그대로 두고, 대신 **그 행위를 하는 순서(한 명씩 차례로)를 자바가 강제로 지키게 만드는 방식**이다. 문 앞에 경비원을 세워서 줄을 세우는 것과 같다.
>
> **② 실제 프로젝트에서 쓴 "컬럼을 수정하는 방식"(원자적 UPDATE)은 정확히 어떤 방식인가**
>
> - 이건 `synchronized`가 아니다. **애초에 "①읽기 → ②계산 → ③쓰기"를 자바 코드가 직접 하지 않도록 만드는 완전히 다른 접근**이다.
> - 기존 방식(문제가 있던 방식): 자바 코드가 ①DB에서 값을 읽어와서(`SELECT`) → ②자바 메모리에서 +1 계산 → ③다시 DB에 저장(`UPDATE`). 이 3단계가 DB를 왔다 갔다 하는 **별개의 요청 3번**이라서, 그 사이에 다른 요청이 끼어들 틈이 있다.
> - 실제로 쓴 방식: `UPDATE playlists SET subscriber_count = subscriber_count + 1 WHERE id = ?`처럼, **"지금 값에 1을 더해라"라는 명령 딱 한 줄**을 DB에 보낸다. 자바 코드는 값을 읽어오지도, 계산하지도 않는다 — 그 일을 통째로 DB에게 맡긴다. DB는 이 한 줄짜리 명령을 실행하는 동안 "읽고-더하고-쓰는" 걸 **한 번의 끊기지 않는 동작**으로 처리하기 때문에, 그 중간에 다른 요청이 끼어들 여지가 아예 없다.
> - **비유**: 화이트보드에 "지금까지 몇 명 왔는지"를 적어두는 상황을 생각해보자.
>   - 기존 방식: 손님이 올 때마다 (1) 화이트보드 숫자를 직접 보고 외운다 → (2) 머릿속으로 +1 계산 → (3) 다시 화이트보드로 가서 적는다. 손님 A가 (1)만 하고 아직 (3)을 안 했는데 손님 B도 (1)을 해버리면, 둘 다 "지금 10이네"라고 보고 둘 다 "11"이라고 적어버린다 → 2명 왔는데 1명만 늘어난 것처럼 보임.
>   - 실제로 쓴 방식: 손님이 화이트보드를 직접 보지도, 계산하지도 않는다. 그냥 화이트보드 옆의 **담당자(DB)**에게 "1명 늘려주세요"라고 말만 한다. 담당자는 보고-계산하고-적는 걸 자기가 한 번의 동작으로 끝내고, 그동안 다른 손님이 끼어들 틈을 안 준다. 여러 손님이 동시에 외쳐도 담당자가 한 명씩 순서대로 처리하니까 절대 숫자가 빠지지 않는다.
>
> **핵심 차이 한 줄 정리**: `synchronized`는 "여러 사람이 직접 손대는 것"은 그대로 두고 **순서만 강제로 통제**하는 방식이고(경비원 세우기), 원자적 UPDATE는 "여러 사람이 직접 손댈 상황 자체를 없애고" **그 일을 한 명(DB)에게 통째로 맡겨버리는** 방식이다. 둘 다 같은 문제(값이 사라지는 것)를 막지만, `synchronized`는 자바 애플리케이션 레벨에서 순서를 관리하고, 원자적 UPDATE는 그 관리를 DB 레벨로 넘겨서 애플리케이션이 신경 쓸 필요조차 없게 만든다는 점이 다르다.
